NOUVEAU (v35) -- ecran noir sur R36S, vraie cause
----------------------------------------------------------------------
- Le dirk.log de la R36S avec la v34 : pour chaque format d'image,
  "Couldn't find matching EGL config". SDL demandait de l'OpenGL de PC
  (notre SDL3 est compile pour PC et consoles a la fois) ; le pilote Mali
  des consoles ne fait que de l'OpenGL ES : aucune configuration ne
  correspondait. SDL ne choisit OpenGL ES tout seul que quand il est
  compile pour une seule marque de puce (Raspberry Pi, Rockchip).
- Dirk demande donc OpenGL ES 2 quand il tourne sans bureau (KMSDRM :
  consoles, Batocera sans X11), et le rendu GLES2 de SDL ; si la fenetre
  echoue quand meme, un second essai avec les reglages de SDL. DIRK_GLES=1
  force le meme choix ailleurs. Lignes "[dirk] screen:" et
  "[dirk] renderer:" dans le log.
Verifie : le test des bezels repasse en entier avec le rendu OpenGL ES
(DIRK_GLES=1, 16 controles sur captures : image, couleurs, bezel) ;
version ARM emulee : lancement OK. Le test des sous-titres echoue ici
depuis que la machine de test n'a plus que 2 processeurs, AVEC ou SANS
ce changement (verifie avec la v34) : delais du test, pas Dirk.
PAS verifie sur une vraie R36S.

  formats.patch, applique tout seul par tools/build_linux_bundle_zig.sh.
- Le lanceur ArkOS ecrit dans dirk.log les messages de SDL sur l'ecran
  (formats essayes, erreurs EGL) et dit quand PortMaster n'est pas trouve.
- Linux : plus de tentative audio "wasapi" (propre a Windows).
Verifie : SDL3 et Dirk reconstruits (x86_64, ARM64, glibc 2.29) ; les 25
tests passent ; lancement sur carte ArkOS simulee. PAS verifie sur une
vraie R36S : le correctif est celui de SDL, le prochain dirk.log dira
quel format a ete retenu ou pourquoi aucun ne passe.

NOUVEAU (v21) -- Dirk Downloader : .zdirk, film et medias a part
----------------------------------------------------------------------
Dans manifest.txt, un jeu peut maintenant avoir 2 ou 3 liens separes
par | :
    Timegal = lien du .zdirk | lien du dossier Movie | lien des medias
    Hayate  = lien du .zdirk | lien du dossier Movie
- lien du .zdirk : "Obtenir le lien" sur le FICHIER .zdirk.
- lien du Movie : sur le dossier Movie (ou un seul fichier film). Un
  dossier nomme Video (jeu Hypseus) reste Video.
- lien des medias (facultatif) : boite 3D, marquee, video... Telecharge
  seulement si le joueur coche "Also download frontend media" (retenu
  d'une fois sur l'autre). Les fichiers arrivent tels quels dans Media\,
  aucune configuration de lanceur.
L'ancienne forme Nom=lien (tout le dossier du jeu) marche comme avant.

Nouvelle colonne Status : Not installed / Up to date / Update available
/ Movie update available / Movie missing / Media update available.
Comment Dirk Downloader sait qu'il y a une mise a jour : il note, dans
un petit fichier cache .dirk-download a cote du jeu, les liens utilises.
Quand tu remplaces un fichier sur Mega, son lien change et tu mets le
nouveau dans le manifest : lien different = mise a jour. Pas de numero
de version a gerer.
En cochant un jeu deja installe, seul ce qui a change est retelecharge
(une mise a jour du jeu = juste le .zdirk, jamais le film). Cfg(reglages, sauvegardes, records) n'est JAMAIS touche ; les fichiers que
le joueur a ajoutes a cote du film (sous-titres, langues) sont gardes.
Un film deja present sans historique (copie a la main) est garde.
Un .zdirk telecharge incomplet est refuse avec un message clair (le
precedent reste en place). Un .zdirk renomme sur Mega remplace l'ancien.

Verifie : downloader\selftest\run.sh -- le vrai code du Downloader, un
faux megatools et un faux Mega, sous Wine : 30 verifications (premiere

qui porte le meme nom. Si le script demande n'est pas dans le zip, le
message donne la liste de ceux qui y sont.
Attention : lancer le DOSSIER (et non un fichier) prend le seul .dirk
qu'il contient, donc le raccourci.

NOUVEAU (v18, revu en v19) -- Jeux zippes (.zdirk), lus sur place
----------------------------------------------------------------------
Un jeu peut tenir en un seul fichier, comme les .zlua de Hypseus : on
zippe le dossier du jeu et on renomme le zip en .zdirk. Double-clic
dessus = le jeu se lance, comme un .dirk.

v19 : le zip est lu SUR PLACE, comme Hypseus. Plus aucune copie du jeu
dans un dossier cache (le %LOCALAPPDATA%\Dirk\zdirk de la v18 ne sert
plus : tu peux l'effacer). Scripts, images, polices, sons, bezels et
controls.cfg sont lus directement dans le zip, en memoire.

Faire un .zdirk (ex. Timegal) :
  1. Dans le dossier du jeu, selectionne tout SAUF Movie (Timegal.dirk,
     Overlay, Fonts, Sounds, Script, Cfg...) > clic droit > Envoyer vers
     > Dossier compresse. (Zipper le dossier Timegal entier, sans Movie,
     marche aussi.)
  2. Renomme le zip en Timegal.zdirk (extensions visibles dans
     l'Explorateur : Affichage > Extensions de noms de fichiers).
  3. Range-le dans un dossier avec seulement le Movie a cote :
        Timegal\Timegal.zdirk
        Timegal\Movie\...
     Les fichiers d'origine NE doivent PAS rester a cote : un fichier
     pose a cote du .zdirk passe avant celui du zip.
  4. Relance l'installeur une fois (il associe .zdirk a dirk.exe), ou
     "Ouvrir avec" > dirk.exe > Toujours.

Ce qui se passe :
- Pour le jeu, son dossier = le dossier du .zdirk, avec le contenu du
  zip "pose dessus" : un fichier present a cote gagne (Custom\, Cfg\...),
  le jeu ecrit a cote comme d'habitude, et les listes de fichiers
  melangent les deux.
- Comme le dossier "ram" de Hypseus : les fichiers Cfg du zip (reglages,
  sauvegardes, records : ce que le jeu modifie) sont copies dans Cfg\ a
  cote du .zdirk au premier lancement, sans jamais ecraser ceux du
  joueur. C'est la seule chose ecrite sur le disque.
- Le film doit etre a cote (deja compresse, et les sauts doivent rester
  instantanes) : un film dans le zip est refuse avec un message clair.
- Ouverture du zip : 1 ms (Dragon's Lair, 111 fichiers).
- Securite : un zip piege (chemins en .., lecteur, chemin absolu) est
  ignore.
- Un zip Hypseus (-zlua) renomme n'est pas encore pris en charge
  (organisation differente).

Verifie :

  script, reglages d'usine, le fichier a cote gagne, rien d'autre ecrit
  sur le disque, listes fusionnees, zips pieges ou abimes. Compile pour

- zdirk_e2e_test (vrai Dirk) : lancement par le .zdirk, par le dossier,

- Vrai KimmyScript : Dragon's Lair en .zdirk (Movie a cote) : attract,

Deja dans la v8 -- Manettes au premier lancement d'un jeu
----------------------------------------------------------------------
Le bug : au tout premier lancement d'un jeu (celui qui affiche l'ecran
INDEXING), aucune manette ni joystick ne fonctionnait, et l'assistant
F9 ne les voyait pas. En relancant, tout marchait.

La cause : au demarrage, Windows (via SDL) annonce chaque manette deja
branchee par un message "manette ajoutee", et Dirk n'ouvre une manette
qu'en recevant ce message. Pendant l'ecran INDEXING, Dirk vide la file
des messages pour que Windows ne croie pas le programme bloque... et
jetait ces messages avec le reste. Au lancement suivant, l'index existe
deja, il n'y a pas d'ecran INDEXING, donc les messages arrivaient.

La correction : pendant l'indexation, les messages "manette ajoutee /
retiree" sont mis de cote, puis rendus au jeu une fois l'index fini.
Rien d'autre ne change.

Verifie : reproduit sans borne avec un joystick et une manette
virtuels. Avant : premier lancement, aucune manette ouverte, aucun
appui recu ; lancement suivant, tout marche. Apres : les deux
lancements ouvrent les deux manettes et recoivent leurs appuis.
Test first_launch_e2e_test. Au total 15 series de tests, toutes OK,
aussi sous AddressSanitizer.

Valide sur ta borne.
